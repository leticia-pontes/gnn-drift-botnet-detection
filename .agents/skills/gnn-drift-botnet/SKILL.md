# GNN Drift Botnet Detection - Specialist Guide

This skill guides agents working on the research project:
**"Avaliação da Resiliência de Redes Neurais de Grafos a Concept Drift na Detecção de Botnets em IoT"** (Author: Letícia Alves de Pontes; Advisor: Prof. Me. Paulo Rogério de Mello Cardoso).

---

## 1. Core Architecture & Mental Model

### 1.1 Objective & Scientific Hypotheses

Evaluate whether Graph Neural Networks (static and dynamic GNNs, with/without pre-training) are statistically more resilient ($\Delta \text{F1} > 10\text{ p.p.}$) to distribution shifts (temporal concept drift and cross-domain shift) in IoT networks compared to standard tabular classifiers (*Random Forest*).

### 1.2 Evaluation Scenarios

- **Scenario T (Temporal Concept Drift - IoT-23):**
  - Dataset: IoT-23 (`conn.log.labeled` generated by Zeek).
  - Train on the oldest network captures; evaluate on the most recent captures in strict chronological order.
  - Split: Derived strictly from `min(ts)` of each capture (80/20 or 70/30). **Never shuffle across time.**
- **Scenario D (Domain Shift - Cross-Dataset):**
  - Train on **IoT-23**, evaluate on **TON-IoT** (Network Dataset).
  - Cross-environment transfer accounting for different physical devices, network topologies, and background noises.

### 1.3 Key Methodological Rules

1. **Never access `.env`:** Configuration and seeds are handled by `src.config.py` and environment variables (`DATA_DIR`, `RESULTS_DIR`, `EXPERIMENT_SEED`).
2. **Fairness Protocol (Isonomy):** If few-shot adaptation or prompt-tuning is used on reserved validation samples for PPT-GNN, all baselines (*Random Forest*, *E-GraphSAGE*, *EvolveGCN-H*) must receive the exact same adaptation budget and samples.
3. **No Leakage Undersampling:** Class balancing (`stratified_train_undersampling`) is applied **exclusively to the training split**. Never alter the class distribution of test splits.
4. **Deterministic Reproducibility:** Always call `src.config.set_seed(42)` before data splits and model training.

## 3. Module APIs & Usage Patterns

### 3.1 `src.config`

* `DATA_DIR`, `PARQUET_DIR`, `RESULTS_DIR`: Paths dynamically resolved based on environment (Colab with/without Drive vs. Local).
* `set_seed(seed=42)`: Fixes Python, NumPy, and PyTorch seeds.

### 3.2 `src.data`

* `download_iot23_lightweight()`: Downloads and unpacks official Stratosphere IoT-23 `conn.log.labeled`.
* `download_ton_iot_kaggle()`: Authenticates via Kaggle API (`~/.kaggle/kaggle.json`) and downloads TON-IoT.
* `read_conn_log_batches(filepath, chunksize=200_000)`: Generator yielding parsed Pandas chunks with low memory overhead.
* `convert_capture_to_parquet(capture_path, output_parquet)`: Converts raw Zeek logs to Snappy Parquet.
* `list_iot23_captures(base_dir)`: Derives start date from `min(ts)` epoch.
* `generate_temporal_splits(captures_df, train_ratio=0.8)`: Strict chronological split `(train_caps, test_caps)`.
* `stratified_train_undersampling(df_train, majority_class=1, minority_class=0, ratio=1.0)`: Balances training data.

### 3.3 `src.harmonization`

Canonical schema (14 columns):
`["ts", "src_ip", "src_port", "dst_ip", "dst_port", "proto", "duration", "orig_bytes", "resp_bytes", "orig_pkts", "resp_pkts", "label", "detailed_label", "dataset_source"]`
* `harmonize_iot23(df)`: Maps Zeek fields (`id.orig_h` $\rightarrow$ `src_ip`, etc.) and casts binary label (0 = Benign, 1 = Malicious).
* `harmonize_ton_iot(df)`: Maps Kaggle TON-IoT fields (`src_bytes` $\rightarrow$ `orig_bytes`, etc.).

### 3.4 `src.graphs`

* **Edge Weight Heuristic:**
  $$w(u, v) = \frac{f(u, v)}{\sum_i f(u, i)}$$
  Computed via `compute_edge_weights(df_flows)`.
* **Temporal Snapshots:**
  `create_temporal_snapshots(df_flows, window_seconds=3600.0, stride_seconds=None)`
* **PyTorch Geometric Data:**
  `build_pyg_graph_data(df_flows, feature_cols=None, node_id_map=None)` $\rightarrow$ `(Data, node_id_map)`.

## 4. Model Roadmap & Protocol

| Model | Type | Input Representation | Implementation Target |
| :--- | :--- | :--- | :--- |
| **Random Forest** | Tabular Baseline | Flat flow features (`NUMERICAL_FEATURE_COLS`) | `src/models/random_forest.py` via `scikit-learn` |
| **E-GraphSAGE** | Static GNN Baseline | Static graph with edge features & weights | `src/models/egraphsage.py` via PyG |
| **EvolveGCN-H** | Dynamic GNN Baseline | Sequence of temporal snapshot graphs | `src/models/evolvegcn.py` via PyG / temporal |
| **PPT-GNN** | Proposed Model | Pre-trained graph + prompt-tuning adaptation | `src/models/ppt_gnn.py` |

### 4.1 Statistical Evaluation & Validation
* **Metrics:** F1-Score (Macro), Precision, Recall, Accuracy, ROC-AUC (OvR Macro).
* **Statistical Significance:** McNemar's test ($\alpha = 0.05$) on pair-wise model predictions.
* **Operational Criterion:** GNN resilience is confirmed if drop in Macro F1 under drift is smaller by $\ge 10\text{ p.p.}$ compared to Random Forest.
* **Repetitions:** 5 runs per model with seeds `[42, 43, 44, 45, 46]`.
