# GNN Drift Botnet Detection - Specialist Guide

This skill guides agents working on the research project:
**"Avaliação da Resiliência de Redes Neurais de Grafos a Concept Drift na Detecção de Botnets em IoT"** (Author: Letícia Alves de Pontes; Advisor: Prof. Me. Paulo Rogério de Mello Cardoso).

---

## 1. Core Architecture & Mental Model

### 1.1 Single Self-Contained Notebook Architecture
The entire codebase lives inside **`notebooks/gnn_drift_botnet_detection.ipynb`** as a self-contained Jupyter Notebook (no external `src/` `.py` files required), so it runs seamlessly on Google Colab (including via the VS Code Colab extension where local repository files are not automatically mounted on the remote VM) as well as locally.

### 1.2 Objective & Scientific Hypotheses
Evaluate whether Graph Neural Networks (static and dynamic GNNs, with/without pre-training) are statistically more resilient ($\Delta \text{F1} > 10\text{ p.p.}$) to distribution shifts (temporal concept drift and cross-domain shift) in IoT networks compared to standard tabular classifiers (*Random Forest*).

### 1.3 Evaluation Scenarios
- **Scenario T (Temporal Concept Drift - IoT-23):**
  - Dataset: IoT-23 (`conn.log.labeled` generated by Zeek).
  - Train on the oldest network captures; evaluate on the most recent captures in strict chronological order.
  - Split: Derived strictly from `min(ts)` of each capture (80/20 or 70/30). **Never shuffle across time.**
- **Scenario D (Domain Shift - Cross-Dataset):**
  - Train on **IoT-23**, evaluate on **TON-IoT** (Network Dataset).
  - Cross-environment transfer accounting for different physical devices, network topologies, and background noises.

### 1.4 Key Methodological Rules
1. **Fairness Protocol (Isonomy):** If few-shot adaptation or prompt-tuning is used on reserved validation samples for PPT-GNN, all baselines (*Random Forest*, *E-GraphSAGE*, *EvolveGCN-H*) must receive the exact same adaptation budget and samples.
2. **No Leakage Undersampling:** Class balancing (`stratified_train_undersampling`) is applied **exclusively to the training split**. Never alter the class distribution of test splits.
3. **Deterministic Reproducibility:** Always call `set_seed(42)` before data splits and model training.

## 2. Structure of `notebooks/gnn_drift_botnet_detection.ipynb`

1. **Section 1 (Environment & Config):** Installs packages (`%pip install`), defines `set_seed`, `get_base_dirs`, and resolves `DATA_DIR`, `PARQUET_DIR`, `RESULTS_DIR`.
2. **Section 2 (Data Ingestion & Zeek Parsing):** `download_iot23_lightweight`, `download_ton_iot_kaggle`, `parse_zeek_header`, `parse_label_columns`, `read_conn_log_batches`, `convert_capture_to_parquet` (using `pyarrow.parquet.ParquetWriter`), `list_iot23_captures`, `generate_temporal_splits`, `stratified_train_undersampling`.
3. **Section 3 (Canonical Schema Harmonization):** 14-column canonical schema (`CANONICAL_COLUMNS`, `NUMERICAL_FEATURE_COLS`), `harmonize_iot23`, `harmonize_ton_iot`, `harmonize_ctu13`.
4. **Section 4 (Graph Construction & Snapshots):** `compute_edge_weights` ($w(u, v) = \frac{f(u, v)}{\sum_i f(u, i)}$), `create_temporal_snapshots`, `build_pyg_graph_data`.
5. **Section 5 (Self-Contained Synthetic Unit Tests):** Validates Zeek parsing, harmonization, edge weights, and PyG `Data` creation in memory.
6. **Section 6 (Scenario T Execution):** Downloads IoT-23, converts to Parquet, plots malicious ratios, and generates temporal splits.
